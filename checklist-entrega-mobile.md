# Checklist de Entrega: Unity 3D Mobile

Use este checklist para orientar os grupos e avaliar o progresso tecnico do projeto Unity 3D Mobile.

## Checklist tecnico minimo

### Projeto

- [ ] Projeto usa o template `3D (Built-in Render Pipeline)`.
- [ ] Projeto usa o `Built-in Render Pipeline`.
- [ ] Projeto abre no Unity sem erros vermelhos no Console.
- [ ] Cena principal esta identificada claramente.
- [ ] Pastas do projeto estao organizadas.
- [ ] Scripts tem nomes compreensiveis.
- [ ] Assets externos foram creditados.

### Gameplay

- [ ] Existe um personagem ou agente controlavel.
- [ ] Existe uma camera funcional.
- [ ] Existe colisao com o cenario.
- [ ] Existe um objetivo claro.
- [ ] Existe uma condicao de vitoria.
- [ ] Existe uma condicao de erro, dano, derrota ou reinicio.
- [ ] O jogo pode ser jogado do inicio ao fim.

### Mobile

- [ ] O grupo definiu quem e responsavel pelo build Android.
- [ ] O projeto foi configurado para Android.
- [ ] A orientacao de tela foi definida.
- [ ] O controle funciona sem teclado no celular ou ha adaptacao planejada.
- [ ] O grupo testou em pelo menos um celular Android.
- [ ] O grupo entregou APK ou video do teste no celular.

### Performance

- [ ] Cena nao depende de graficos realistas.
- [ ] Quantidade de luzes e sombras foi controlada.
- [ ] Modelos 3D pesados foram evitados.
- [ ] Particulas foram usadas com moderacao.
- [ ] Texturas externas nao sao grandes demais.
- [ ] O jogo nao trava durante o video de demonstracao.

## Rubrica sugerida para A3

Total: 40 pontos.

| Criterio | Pontos | O que observar |
|----------|--------|----------------|
| GDD e planejamento | 5 | Ideia clara, escopo realista, papeis do grupo |
| Jogabilidade basica | 10 | Movimento, camera, colisao, objetivo |
| Logica de jogo | 8 | Pontuacao, vitoria, derrota, scripts funcionando |
| Adaptacao mobile | 7 | Build Android, controles touch, teste em celular |
| Computacao grafica | 5 | Uso adequado de cena 3D, materiais, luz, camera |
| Polimento e apresentacao | 5 | Audio, UI, feedback, video e organizacao |

## Penalidades sugeridas

- Projeto nao abre: ate -10 pontos.
- Nao ha gameplay jogavel: ate -15 pontos.
- Nao ha evidencia de teste mobile: ate -7 pontos.
- Uso de template pronto sem modificacao significativa: ate -15 pontos.
- Grupo nao credita assets externos: ate -5 pontos.

## Evidencias aceitas

Evidencias usadas ao longo da trilha:

- video do Editor;
- video do celular;
- APK;
- prints do Build Settings;
- prints do Console;
- link para repositorio;
- pacote `.zip` do projeto;
- diario curto do grupo explicando decisoes tecnicas.

## Pontos de acompanhamento

O grupo deve receber orientacao especifica quando:

- ainda nao criou projeto;
- escolheu ideia grande demais;
- nao sabe quem fara o build Android;
- ainda nao apresentou evidencia de configuracao Android;
- esta usando assets pesados antes da logica funcionar;
- nao consegue explicar a condicao de vitoria;
- mostra apenas cenario bonito, sem interacao.

## Ajuste de escopo

Quando o escopo precisar ser ajustado, o projeto pode ser concentrado em:

1. uma sala;
2. um jogador;
3. tres objetos coletaveis;
4. uma porta de saida;
5. mensagem de vitoria;
6. video rodando no Editor ou no celular.

Esse escopo ainda permite avaliar Unity, logica, 3D, interacao e mobile dentro dos objetivos da disciplina.
